# SOCRATOBOT

#### Description:
Socratobot is where ancient philosophy meets modern AI. Inspired by the idea that the Greek philosopher Socrates would debate anyone on anything, in what would come to be known as 'Socratic Dialogue' or the 'Socratic Method', Socratobot helps users to hone their critical thinking skills and question not just what they believe, but why they believe it. With a little help from a friendly chatbot.

Users submit a belief or idea. Socratobot will then question them, prompting them to respond with thoughtful written responses. After five rounds of exchange, Socratobot will rate the user's responses and give them a score out of 10. The more comprehensive and well-reasoned the responses have been, the higher the score. Socratobot will also offer helpful feedback on how the user could improve and aspects they could consider.


#### Technologies: How does it work?
Socratobot is a Flask-based application which is built on top of Cohere's API. It utilises JavaScript in the frontend and Python in the backend to create an interactive AI chatbot, with JSON used for data exchange as it is supported by both languages.

The frontend sends user input, such as messages to the chat, in HTTP requests formatted as JSON strings using JavaScript's JSON.stringify. These POST requests are sent to the /chat route in the backend, where Flask automatically parses them into Python dictionaries using request.json. This allows the backend to access the ‘message’ field and read the user's input to the chatbot.

The backend sends responses, including chatbot replies generated by Cohere or system error messages, to the frontend as JSON using Flask's jsonify function, which converts Python dictionaries into JSON with correct HTTP headers (ensuring the frontend JavaScript interprets the response as JSON). Without the use of jsonify, the Python dictionaries would have to be manually converted to JSON strings using json.dumps, which is less concise and more prone to error. The frontend therefore expects JSON for all communications so jsonify is used across all API routes for consistency. Once received, the frontend JavaScript parses the JSON responses for display.

Since the back-and-forth retrieval of messages does present many possibilities for errors, try/except blocks within the route functions in the Python scripts for both the Flask app and the chatbot are utilised. This means errors are both handled gracefully and correctly logged for debugging. The try/except blocks also ensure that errors are caught and returned as a JSON, displayed either in the chat or modals, helping to prevent app crashes. Python's logging module is used to record events for debugging.


#### Design
The main feature of Socratobot is the chatbot itself, and so modal windows as overlaying elements are used instead of multiple HTML pages, which means you are never more than a click away from returning to the chatbot conversation.

The page design and colour palette are Greek-inspired with the primary aim to make the chatbot as clear and easy to interact with as possible, while leaning into the chatbot's original inspiration.

Design consistency (including fonts and the gold/blue/parchment colour scheme) is maintained via CSS. The web pages are built using HTML, with the base structure saved in base.html. Interactivity, including certain buttons/features being available only to logged-in individuals with an account, is maintained using JavaScript, with Jinja handling static templating.

Socratobot does have an avatar (stored as a png image) which is designed to align with the latest message the bot has sent in the chat. This helps create the illusion that the user is 'speaking' to a digital philosophy teacher. The avatar was designed using Grok image generation and based on Socrates himself, though heavily cartoonised.


#### Features
##### Chatbot
The chatbot is built upon Cohere's 'command-a' model and is Socratobot's central feature. The 'character' and behaviours have been entered via detailed and rigorously tested preambles, which instruct the chatbot how to talk and how to engage with users primarily via Socratic Dialogue -- asking questions rather than giving answers like a regular AI.

This includes separate preambles for the main chatbot behaviour and for the feedback/scoring mechanic. These preambles were hand-written and, throughout the building process, were expanded upon in conjunction with the "temperature" of the chatbot to ensure that it spoke and responded in the desired manner.

The chat input box is manually adjustable, in case the user wants to type more lengthy answers. There is also a 'Reset' button which clears the current chat entirely.

##### Scoring system
After five rounds of dialogue, Socratobot provides the user with a score based on how well-reasoned it believes the responses to have been. In addition, Socratobot will also provide feedback on how the user's reasoning and responses could be improved. In this sense, Socratobot is supposed to act more as a teacher and mentor, helping the user to improve how they defend their arguments.

##### Instructions & Info
A simple modal pop-out which contains information on Socrates (the inspiration behind Socratobot), along with instructions on how to use the chatbot

This stores their details in socratobot.db and assigns them a unique integer ID.

##### Contact & Disclaimer
The is the option to contact the user (me) via LinkedIn to report any bugs or feedback. There is also a disclaimer included in the instruction page which emphasises Socratobot's use for education and fun, not as any kind of replacement for educational professionals or medical help, and that AI can make mistakes/errors.

##### Future Features
Some features I would like to implement in the future would be:

* Pre-populated statements: Users can start the conversation with Socratobot with a randomly-generated statement or belief, which they will then have to defend. This would be a library of statements which offer ample grounds for critical thinking, such as "There is no such thing as universal justice" or "People are naturally inclined towards selfishness".

* Timer: Users have to enter their response to Socratobot within a set amount of time (with different options depending on how challenging they'd like this to be).

* Enhanced registration: Allow users to register with Socratobot via their Google or GitHub account, along with resetting or recovering their login details.

* Animations: There is sometimes a delay when waiting for Socratobot's response, especially the longer 'feedback' messages; these could be covered by animating the Socratobot avatar so he appears to be "thinking" about the next response.

* Hosting: Socratobot is currently hosted on render.com which does take time to load, in the future it would be easier and more convenient to host the app on its own web page.

#### File Explanations:
* app.py: Main Flask application script, which contains the central backend logic for Socratobot. This includes creating the web server, key route functions for the main features, and setting up the SQLite database. Session data is handled in this file, along with user authentication and logging for debugging.

* chatbot.py: A separate Python script specifically to handle logic for the chatbot itself. This includes the preambles, chat history, error handling and initialising the Cohere API client with a secure API key for chatbot responses.

* styles.css: Defines the visual styles for the Socratobot web page. This includes the fonts, colour scheme and layout which create the Ancient Greek aesthetic for the chat interface, buttons and modal pop-outs to ensure design consistency.

* script.js: Handles dynamic design elements and interactivity in the front-end of Socratobot. This includes displaying the chat messages, smooth interaction with the modal pop-outs, status updates for logging in/out, and ensuring the avatar dynamically moves to stay in line with the latest bot message.

* base.html: Provides the structural template for HTML files, using Jinja syntax to create a placeholder block that can be overridden, allowing for customisable HTML content while ensuring the core structure stays consistent.

* index.html: The main webpage for Socratobot, which extends on base.html and overrides the placeholder block with the web content, page layout, modals and navigation elements, with design styled via CSS.

* socrates.png: The Socratobot avatar, stored as a png image.
